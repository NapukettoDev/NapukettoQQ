统一环境变量前缀为 `NAPUKETTO_*`，并移除全部旧前缀兼容逻辑（破坏性变更）。

**行为变化**：不再是「新前缀优先、旧前缀回退」。旧拼写（历史 `NAPKETTO_*` 与 `NAPUTO_*`
两族）既不会被读取，也不会被别名翻译后透传给自宿主子进程——传了就是无效配置。此前
`NAPKETTO_LOG_LEVEL` 规范化、`NAPUTO_*` 控制标记透传、`NAPKETTO_CONFIG_JSON` 双读这几条
兼容路径已全部删除。原先只认旧名的变量（QQ 定位、7-Zip、Linux stub/HOME、Windows node、
内联配置白名单、supervisor 托管标记等）一并切到规范前缀。

**迁移对照**（部署侧需要一次性改名；`NAPUTO_` 与 `NAPKETTO_` 一律换成 `NAPUKETTO_`）：

| 旧名 | 新名 |
|---|---|
| `NAPKETTO_CONFIG_JSON` / `NAPKETTO_CONFIG` / `NAPKETTO_DATA` | `NAPUKETTO_CONFIG_JSON` / `NAPUKETTO_CONFIG` / `NAPUKETTO_DATA` |
| `NAPKETTO_LOG_LEVEL` / `NAPKETTO_REGISTRY` / `NAPKETTO_NPM_OTP` | `NAPUKETTO_LOG_LEVEL` / `NAPUKETTO_REGISTRY` / `NAPUKETTO_NPM_OTP` |
| `NAPUTO_CFG_DIR` / `NAPUTO_DATA_ROOT` | `NAPUKETTO_CFG_DIR` / `NAPUKETTO_DATA_ROOT` |
| `NAPUTO_KERNEL_ENTRY` / `NAPUTO_ADAPTER_ENTRY` / `NAPUTO_NETWORK_ENTRY` | `NAPUKETTO_KERNEL_ENTRY` / `NAPUKETTO_ADAPTER_ENTRY` / `NAPUKETTO_NETWORK_ENTRY` |
| `NAPUTO_WRAPPER_PATH` / `NAPUTO_QQ_VERSION` / `NAPUTO_QQ_PATH` | `NAPUKETTO_WRAPPER_PATH` / `NAPUKETTO_QQ_VERSION` / `NAPUKETTO_QQ_PATH` |
| `NAPUTO_QQ_FILES` / `NAPUTO_QQ_DIR` / `NAPUTO_QQ_URL` | `NAPUKETTO_QQ_FILES` / `NAPUKETTO_QQ_DIR` / `NAPUKETTO_QQ_URL` |

| `NAPUTO_QUICK_UIN` / `NAPUTO_QR_ONLY` / `NAPUTO_IPC` / `NAPUTO_DIAG` | `NAPUKETTO_QUICK_UIN` / `NAPUKETTO_QR_ONLY` / `NAPUKETTO_IPC` / `NAPUKETTO_DIAG` |
| `NAPUTO_SMOKE` / `NAPUTO_SMOKE_PEER` / `NAPUTO_PROBE` / `NAPUTO_LISTENER_RECORD` | `NAPUKETTO_SMOKE` / `NAPUKETTO_SMOKE_PEER` / `NAPUKETTO_PROBE` / `NAPUKETTO_LISTENER_RECORD` |
| `NAPUTO_SELF_HOST` / `NAPUTO_SUPERVISOR_CHILD` | `NAPUKETTO_SELF_HOST` / `NAPUKETTO_SUPERVISOR_CHILD` |

**保持不变的原生契约**：闭源 `native/` 二进制硬编码读取的 `NAPUTO_DISABLE_MEDIA_PATCH`
（补丁 killswitch）与 `NAPUTO_MEDIA_PATCH_STATUS`（补丁状态文件路径）仍是原拼写，禁止改名；
stdout 二维码行协议前缀 `NAPUTO_QR ` 也不是环境变量，同样保持不变。

Docker 部署（`docker/Dockerfile`、`docker/docker-entrypoint.sh`、`docker/compose.yaml`）
与模板/文档已同步；`launchSelfHost` 的环境白名单不再识别任何旧拼写。
